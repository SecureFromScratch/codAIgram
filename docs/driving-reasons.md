# Driving reasons and future constraints

The initial screen exists to make the core loop tangible: write a class description and immediately see a corresponding structure. The relationship notation stays in the source text and creates a labelled ownership connector, a separate target node, and a many marker.

As the product grows, parse and validate into a renderer-independent model with stable semantic identities. Add source maps and targeted edits before allowing the canvas to change meaning. Store visual overrides separately. When adding Yjs, authorize document access before joining rooms, limit message/document sizes, and keep awareness ephemeral. AI must return validated proposals tied to a revision; never let a model write directly to canonical state. Keep secrets on the server. Persistence and authentication remain explicit open decisions.
