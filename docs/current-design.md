# Current design

The first release is a single browser-local editing session: CodeMirror holds the text; a small pure parser produces a semantic diagram; a JointJS adapter renders it. A heading names each class; classes are separated by blank lines, and properties have required types. Method declarations start with exactly two spaces; while their parentheses are open they may continue on lines indented at least four spaces. Tabs do not count as indentation. Whitespace around method parameters and ownership punctuation is accepted. The editor scrolls horizontally instead of visually wrapping. The diagram shows method names, with signatures and parameter types in hover tooltips. `OWNS field: Type[]` creates a target class and a labelled connector with a filled owner-side diamond and a `*` at the target; the ownership declaration is not a method row. Invalid method edits retain the last valid graph; recoverable ownership edits update the graph with a diagnostic. This is a provisional grammar, not the complete language. Text and graph are not saved. The canvas is read-only and no AI, authentication or collaboration is implemented.

The in-memory class document retains the last valid class definitions. The editor shows a selected subset; valid changes update the document, while invalid drafts remain visible and do not replace the retained definitions. The graph projects the document, including classes hidden from the editor. Eye badges indicate visible classes; click toggles visibility and double-click isolates one class. An empty editor does not erase the document. The current syntax, recoverable ownership editing, and editor highlighting are defined in [class-diagram-dsl.md](class-diagram-dsl.md).

The Mandate Express server provides `GET /health`, `POST /api/classesDetails` for a bounded list of class names, and `POST /api/updateClasses` for a bounded JSON array of class details. The update validates the entire batch and atomically creates or replaces the named documents; it responds with `{ "updated": number }` and rejects duplicate names. The repository uses a Firestore Native-mode emulator. The server currently requires a loopback emulator, not a cloud database, and does not implement authentication or authorization. An explicit create-only seed populates missing example documents; tests use a separate collection. At startup the client requests `ClassDiagram` and `Class`, then derives the initial editor text from the former. Editor edits are not automatically saved. Vite proxies API requests during local development. Run instructions are in the root README. Local packages are built and staged by bootstrap; application builds invoke both general and React gates.

Example update request body (one to 100 entries):

```json
[{"name":"Example","methods":["run(value: string)"],"relations":[{"kind":"OWNS","name":"items","target":"Item","many":true}],"isPartial":false}]
```

Each update replaces the complete stored class, not just selected fields. The request body is limited to 256 KiB; each class has at most 100 methods and 100 relations. The endpoint is intended for the existing local-only development server and is not safe to expose publicly without authentication, authorization, and browser request protections.
