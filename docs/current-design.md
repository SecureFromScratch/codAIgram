# Current design

The client has Classes and Tests modes. Classes is a browser-local editing session: CodeMirror holds the text; a small pure parser produces a semantic diagram; a JointJS adapter renders it. A heading names each class; classes are separated by blank lines, and properties have required types. Method declarations start with exactly two spaces; while their parentheses are open they may continue on lines indented at least four spaces. Tabs do not count as indentation. Whitespace around method parameters and relationship punctuation is accepted. The editor scrolls horizontally instead of visually wrapping. The diagram shows method names, with signatures and parameter types in hover tooltips. `OWNS`, `REF`, and `UNK` use `KIND field: Type[]` declarations. `OWNS` creates a target class and a labelled connector with a filled owner-side diamond and a `*` at a many-valued target; `REF` is a directed reference; `UNK` is a dashed unknown connection. Relationship declarations are not method rows. Invalid method edits retain the last valid graph; recoverable relationship edits update the graph with a diagnostic. This is a provisional grammar, not the complete language. Text and graph are not saved. The canvas is read-only and no AI, authentication or collaboration is implemented. Tests has no text editor: its left pane reads the persisted tests inventory and presents a tree of test groups and cases. Its right pane is deliberately a placeholder until a test-flow or sequence-diagram design is chosen.

The in-memory class document retains the last valid class definitions. The editor shows a selected subset; valid changes update the document, while invalid drafts remain visible and do not replace the retained definitions. The graph projects the document, including classes hidden from the editor. Eye badges indicate visible classes; click toggles visibility and double-click isolates one class. An empty editor does not erase the document. The current syntax, recoverable ownership editing, and editor highlighting are defined in [class-diagram-dsl.md](class-diagram-dsl.md).

The Mandate Express server provides `GET /health`, `GET /api/getClasses` for the complete class inventory, `POST /api/classesDetails` for a bounded list of class names, and `POST /api/updateClasses` for a bounded JSON array of class details. A class member is `{ name, overloads }`, where `overloads` is an args list of `{ arg, t }` fields. A composite `t` is either a type-expression string or a recursively keyed object. Method fields use parameter names; variables and properties use exactly one `+RO`, `+RW`, `+GET`, `+SET`, or `+PROP` marker and carry the member type. The update validates the entire batch and atomically creates or replaces the named documents; it responds with `{ "updated": number }` and rejects duplicate names. It also provides `POST /api/updateTests` and `GET /api/getTests` so Scanner can upsert and retrieve its bounded local test inventory by group and case name. The repository uses a Firestore Native-mode emulator. The server currently requires a loopback emulator, not a cloud database, and does not implement authentication or authorization. The manual workbench starts an unseeded emulator and persists its local export under `.workbench/firestore`; ordinary API and browser tests use deterministic in-memory repositories, while Firestore integration tests create and clean up their own test data. At startup the client retrieves the complete inventory, derives the initial editor text from its first class, and projects every returned class. Editor edits are not automatically saved. Vite proxies API requests during local development. Run instructions are in the root README. Local packages are built and staged by bootstrap; application builds invoke both general and React gates.

Example update request body (one to 100 entries):

```json
[{"name":"Example","methods":[{"name":"run","overloads":[{"arg":"value","t":"string"}]}],"relations":[{"kind":"OWNS","name":"items","target":"Item","many":true}],"isPartial":false}]
```

Each update replaces the complete stored class, not just selected fields. The request body is limited to 256 KiB; each class has at most 100 methods and 100 relations. The endpoint is intended for the existing local-only development server and is not safe to expose publicly without authentication, authorization, and browser request protections.
